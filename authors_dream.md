# Author's Dream

This file is different from `USER_INPUT_RECORD.md`. That file is a verbatim record of founding
*architectural* statements, each pulled apart into a technical response. This one is written in the
author's other voice — he is a science-fiction writer as well as this project's creator — and reads
like fiction rather than a spec. Don't mistake that for the content not mattering: these entries are
requirements too, specifically for OAG's applications in space (long-haul/high-latency links,
sensor networks and craft with no fixed ground station, identity and trust across communication
blackouts), written as scenes and dreams because that's the clearest way the author has of
describing a requirement that doesn't have a name yet. Treat a detail stated here the same as a
detail in `USER_INPUT_RECORD.md`: don't invent scenes on the author's behalf, don't resolve one into
a spec change without being asked, and don't edit an entry after it's written — only append.

Entries land here when the author adds them.
